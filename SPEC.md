## Як користуватися цим ТЗ

Це один документ, який одночасно є технічним завданням і промптом для Claude Code: експортуй його в Markdown, поклади в корінь репозиторію як `SPEC.md` і перше повідомлення агенту зроби таким: «Прочитай SPEC.md повністю. Почни з розділу "Протокол роботи". Не пиши код, доки не покажеш план Етапу 0».

Розділи з 2-го по 16-й адресовані агенту в другій особі («ти»). Все, що позначено **MUST**, — обов'язково; **SHOULD** — бажано; **NOT NOW** — свідомо відкладено, агент не має це будувати без твого прямого дозволу.

Порядок роботи: Етап 0 (каркас) → Етап 1 (тест уваги) → Етап 2 (Форма й історія) → Етап 3 (експерименти) → Етап 4 (полірування й запуск). Фаза 2 (Пульс країни) — лише після того, як MVP має перших живих користувачів.

Працюй з агентом короткими сесіями: один етап — одна гілка — одна перевірка на твоєму телефоні. Якщо агент пропонує додати бібліотеку, фічу чи бекенд, якого тут нема, — це сигнал зупинитись і перечитати розділ «Не-цілі».

## Рішення: веб-застосунок (PWA), не нативний

NeRN будуємо як прогресивний веб-застосунок (PWA): відкривається за посиланням, встановлюється на домашній екран, працює офлайн. Нативний Android — **NOT NOW**.

| Критерій | PWA | Нативний Android |
| --- | --- | --- |
| Хто може спробувати | Будь-хто за посиланням, включно з людиною, що читає заявку | Лише Android, треба встановити |
| Точність часу реакції | ±1 кадр (\~8–17 мс), стабільна в межах одного пристрою | Трохи краща, але різниця не критична |
| Швидкість розробки з Claude Code | Висока, один код для всіх | Нижча, окремий тулчейн |
| Приватність | Дані в IndexedDB на пристрої, сервера нема | Так само можливо |
| Сповіщення | Обмежені на iOS, тільки після встановлення на екран | Повні |
| Уже є | nern.netlify.app | Нічого |

Головний аргумент: читач заявки не встановлюватиме застосунок, але натисне посилання і за 90 секунд пройде тест. Похибка браузера (\~1 кадр) менша за ефекти, які нас цікавлять (десятки мілісекунд між «виспалась» і «ні»), і однакова для одного пристрою — а ми порівнюємо людину лише з нею самою.

Компроміс, який приймаємо свідомо: нагадування на iOS працюють лише після встановлення PWA на домашній екран. Тому MVP не покладається на push — ритуал тримається на ранковій звичці й коротких посиланнях.

## Промпт-ядро: роль, місія, принципи, не-цілі

**Роль.** Ти — senior-інженер фронтенду і продуктовий дизайнер, що будує NeRN разом зі мною (засновницею, не професійною розробницею). Пиши код, який я можу прочитати й пояснити. Простота важливіша за «розумність».

**Місія.** NeRN — це 90-секундний тест уваги, з яким людина ставить експерименти над власним життям (сон, скрол, кава), а дані ніколи не залишають її телефон.

**Позиціонування (дослівно, для лендингу):** «Застосунок, якому неможливо збрехати — і який не може тебе видати». Метафора всього продукту: **дзеркало, а не монітор**.

**Принципи продукту (MUST):**

1. Людина порівнюється лише з собою. Жодних рейтингів, «ти гірший за середнього», таблиць лідерів.
2. Чесність замість мотивації. Якщо даних замало або різниця в межах шуму — так і пишемо.
3. Сигнал, а не діагноз. NeRN не медичний пристрій і ніде не робить медичних висновків.
4. Приватність як архітектура: без акаунта, без сервера, без аналітики третіх сторін у MVP.
5. Без провини. Пропущений день — це не «зламана серія», а просто пропущений день (тон — як у Gentler Streak).
6. Не пропонувати видалити соцмережі. NeRN показує ціну звички, а рішення лишається за людиною.
7. 90 секунд від відкриття до результату. Все, що заважає, — прибрати.

**Не-цілі (NOT NOW, не будувати без прямого дозволу):**

- ШІ-чати, LLM-виклики, генерований текст.
- Автоматичне зчитування використання телефона, геолокації, сенсорів, мікрофона.
- Соцфункції, друзі, шеринг станів іншим людям.
- Акаунти, логін, хмарна синхронізація.
- Користувачі до 18 років.
- Нативні застосунки, React Native, Capacitor.
- Рядок «як після N годин сну» — лише після валідації на реальних даних.
- Keystroke dynamics (калібрувальна фраза) — окрема задача після MVP.

**Сценарій B — щоденний ритуал (≤ 2 хв):** відкрити з домашнього екрана → «Почати» → тест → Форма дня + короткий чек-ін (сон, настрій, тег експерименту) → закрити.

**Сценарій C — експеримент (2 тижні):** обрати звичку з бібліотеки або написати свою → застосунок щодня каже, яка сьогодні умова (A чи B) → після мінімуму даних показує вердикт → людина вирішує, що робити далі.

**Сценарій D — «Ціна скролу» (SHOULD, Етап 4):** швидкий тест → скрол → швидкий тест, з явним підписом «це сигнал, а не висновок».

## Стек, архітектура, структура репозиторію

MVP — це повністю клієнтський застосунок без бекенда: статичні файли на Netlify (вже є nern.netlify.app), усі дані в IndexedDB на пристрої.

| Шар | Вибір | Чому |

| Стилі | Tailwind CSS + CSS-змінні для токенів | Токени дизайн-системи в одному місці |

| Анімація | Motion (колишній Framer Motion), лише для переходів | Стриманий рух; тест уваги — без бібліотек |

## Модель даних (IndexedDB)

Три таблиці (Profile, Session, Experiment), усі локальні; Trial і CheckIn вкладені в Session. Зберігаємо сирі реакції кожного сеансу, щоб метрики можна було перерахувати, якщо формула зміниться.

```ts
// db/schema.ts — Dexie, version(1)

interface Profile {
  id: 'me';                       // один запис
  createdAt: number;              // epoch ms
  locale: 'uk' | 'en';
  ageConfirmed18: true;           // без true застосунок не зберігає дані
  consentVersion: string;         // напр. '2026-10-01'
  preferredWindow?: { startHour: number; endHour: number }; // звичне вікно тесту
  region?: string;                // ЛИШЕ для Фази 2, обирає людина, за замовчуванням порожньо
}

interface Session {
  id: string;                     // crypto.randomUUID()
  startedAt: number;              // epoch ms
  localDate: string;              // 'YYYY-MM-DD' у часовому поясі пристрою
  localHour: number;              // 0–23
  mode: 'daily' | 'quick' | 'demo';
  durationMs: number;             // заплановано: 90000 (daily), 60000 (quick)
  trials: Trial[];
  device: DeviceInfo;
  validity: Validity;
  metrics?: SessionMetrics;       // рахується stats/, null якщо невалідний
  checkIn?: CheckIn;
  experimentId?: string;
  condition?: 'A' | 'B';
}

interface Trial {
  isiMs: number;                  // запланована пауза перед стимулом
  onsetTs: number;                // performance.now() кадру показу
  responseTs: number | null;      // performance.now() з pointerdown
  rtMs: number | null;            // responseTs - onsetTs
  kind: 'valid' | 'lapse' | 'false_start' | 'miss';
}

interface DeviceInfo {
  fingerprint: string;            // хеш від: платформа + ширина/висота екрана + частота кадрів
  refreshHz: number;              // оцінено перед тестом
  inputType: 'touch' | 'mouse' | 'pen';
}

interface Validity {
  ok: boolean;
  reasons: Array<'tab_hidden' | 'too_few_trials' | 'too_many_false_starts' | 'frame_drops' | 'interrupted'>;
}

interface SessionMetrics {
  medianRtMs: number;
  meanSpeed: number;              // середнє 1000/RT для валідних реакцій, одиниці: 1/с
  lapses: number;                 // RT >= 355 мс
  falseStarts: number;            // реакція < 100 мс або до стимулу
  validTrials: number;
}

interface CheckIn {
  sleepHours?: number;            // крок 0.5
  sleepQuality?: 1 | 2 | 3 | 4 | 5;
  mood?: 1 | 2 | 3 | 4 | 5;
  nightAlert?: boolean;           // «була тривога вночі» — ставить сама людина
  tags: string[];                 // напр. ['coffee', 'reels_before_bed']
  note?: string;                  // до 140 символів, ніколи не аналізується
}

interface Experiment {
  id: string;
  title: string;                  // 'Телефон поза спальнею'
  conditionA: string;             // 'Телефон у спальні (як зазвичай)'
  conditionB: string;             // 'Телефон за дверима'
  schedule: 'alternating' | 'blocks';
  startedAt: number;
  plannedDays: number;            // 14 за замовчуванням
  status: 'running' | 'done' | 'abandoned';
  source: 'library' | 'custom';
}
```

**MUST:** експорт усіх даних у JSON і CSV однією кнопкою; повне видалення однією кнопкою з підтвердженням; схема з версіями й міграціями Dexie з першого дня.

## Тест уваги (PVT): точні параметри

Основа — Psychomotor Vigilance Test, короткий варіант PVT-B за [Basner et al., 2011](https://www.med.upenn.edu/uep/assets/user-content/documents/Basner2011-ValidityandsensitivityofabriefPVT.pdf): пауза між відповіддю і наступним стимулом 1–4 с, провал (lapse) — реакція ≥ 355 мс, фальстарт — реакція < 100 мс. Людина бачить лічильник мілісекунд, що запускається в центрі екрана, і якнайшвидше торкається екрана.

**Чесне обмеження, яке агент має врахувати в текстах:** навіть 3-хвилинна версія погано збігається з повною 10-хвилинною в частині досліджень ([Frontiers in Neuroscience, 2022](https://www.frontiersin.org/journals/neuroscience/articles/10.3389/fnins.2022.815697/full)). Наш 90-секундний тест ще шумніший. Тому NeRN ніколи не робить висновків з одного сеансу — лише з трендів і порівнянь багатьох днів.

| Параметр | Щоденний (daily) | Точний (для експериментів, SHOULD) | Швидкий (quick / демо) |
| --- | --- | --- | --- |
| Тривалість | 90 с | 180 с (PVT-B) | 60 с |
| Пауза до стимулу | 1–4 с, рівномірний розподіл | 1–4 с | 1–4 с |
| Показ результату після реакції | 1000 мс (зупинений лічильник) | 1000 мс | 1000 мс |
| Тайм-аут без реакції | 10 с → miss, рахується як провал | 10 с | 10 с |
| Очікувано стимулів | \~20–25 | \~40–50 | \~14–17 |
| Мінімум для валідності | ≥ 15 валідних реакцій | ≥ 30 | ≥ 10 |

**Правила рушія (MUST):**

1. Пауза рахується від моменту відповіді до наступного стимулу. Послідовність пауз генерується наперед зі зафіксованим seed (для тестів).
2. Момент показу стимулу: зміну DOM робимо в колбеку `requestAnimationFrame`, а `onsetTs` фіксуємо в **наступному** колбеку rAF (кадр уже показано). Похибка стала для пристрою, тому для порівняння із собою вона не заважає.
3. Момент реакції: `event.timeStamp` з `pointerdown` на повноекранному елементі (не `click`, не `touchend`). `rtMs = timeStamp - onsetTs`.
4. Лічильник мілісекунд оновлюється в rAF і нічого не рахує сам — це лише візуалізація.
5. Дотик без стимулу = фальстарт: показати «Зарано» на 1 с і згенерувати нову паузу. Без звуків, без вібрації, без червоного кольору.
6. Під час тесту: `touch-action: none`, заборонене виділення тексту й контекстне меню, `navigator.wakeLock` (якщо доступний), жодних анімацій, крім самого стимулу.
7. Якщо `document.visibilityState` стає `hidden` — сеанс позначається `interrupted`, дані зберігаються, але не входять у метрики.
8. Перед тестом 1 с вимірювати частоту кадрів (середній інтервал rAF). Якщо під час тесту > 10% кадрів довші за 1,5 × норми — позначка `frame_drops`.
9. Перший у житті сеанс починається з 3 тренувальних стимулів, які не рахуються.
10. Зміна пристрою (інший `fingerprint`) починає новий сегмент базової лінії; старі дані не змішуються з новими в Формі.

Калібрувальна фраза (keystroke dynamics) — **NOT NOW**: у MVP її немає, модуль рушія має бути написаний так, щоб її можна було додати пізніше як окремий крок.

## Метрики, Форма, експерименти: формули й правила

Головна метрика — швидкість відповіді (середнє 1/RT), бо в літературі з PVT вона найчутливіша до недосипу. Усі функції лежать у `src/stats/` як чисті функції з юніт-тестами.

**Метрики сеансу.** Відповіддю вважається дотик з RT ≥ 100 мс. Пропуск (miss) рахується як відповідь з RT = 10 000 мс. Для n відповідей:

```latex
S = \frac{1}{n}\sum_{i=1}^{n} \frac{1000}{RT_i} \quad [1/\text{с}]
```

Провали = кількість відповідей з RT ≥ 355 мс (разом із пропусками). Медіана RT показується як зрозуміле людині число («твоя типова реакція — 284 мс»).

**Калібрування.** Перші 5 валідних щоденних сеансів на пристрої — калібрування: замість відсотка Форми показуємо «Калібрування 3/5» і пояснення, що мозок звикає до тесту.

**Форма дня.** Стеля C — 90-й перцентиль S серед валідних щоденних сеансів поточного сегмента пристрою за останні 60 днів (калібрувальні не рахуються).

```latex
\text{Форма} = \min\left(100,\ \operatorname{round}\left(100 \cdot \frac{S_{\text{сьогодні}}}{C}\right)\right)
```

Якщо S сьогодні > C, показуємо 100 і позначку «новий пік». Замість довільних порогів (зелений/червоний) показуємо **звичний діапазон** — міжквартильний інтервал Форми за 60 днів — і один із трьох підписів: «вище звичного», «у звичних межах», «нижче звичного». Ніяких червоних кольорів і слів «погано».

**Експерименти (MUST):**

1. Одночасно активний лише один експеримент.
2. Розклад за замовчуванням — перемішані пари днів: у кожній парі один день A й один B у випадковому порядку (seed зберігається). Блоки «7 днів A, потім 7 днів B» — лише як опція з попередженням, що так на результат впливає звикання до тесту.
3. Для вечірніх звичок умова стосується вечора, а тест наступного ранку отримує цю умову. Ранковий чек-ін питає: «Вчора вдалося дотриматись умови?» Якщо ні — сеанс виключається з аналізу.
4. Калібрувальні сеанси й сеанси поза звичним вікном тесту (±2 год) виключаються; застосунок м'яко нагадує тестуватись в один і той самий час.

Різниця між умовами (у відсотках):

```latex
\Delta = 100 \cdot \frac{\bar{S}_B - \bar{S}_A}{\bar{S}_A}
```

95% довірчий інтервал для Δ — bootstrap: 5000 перевибірок сеансів усередині кожної умови, перцентильний інтервал, фіксований seed (щоб результат не «стрибав» при повторному відкритті).

| Умова | Вердикт українською | Вердикт англійською |
| --- | --- | --- |
| < 5 валідних сеансів у будь-якій умові | «Поки замало даних: ще N днів» | Not enough data yet |
| Інтервал не містить 0, Δ > 0 | «З умовою B твоя увага помітно краща: приблизно на X%» | Noticeably better with B |
| Інтервал не містить 0, Δ < 0 | «З умовою B твоя увага помітно гірша: приблизно на X%» | Noticeably worse with B |
| Інтервал містить 0 | «Різниця в межах шуму. Це теж результат» | Within the noise — that's a result too |

Заборонені формулювання: «статистично значуще», «доведено», «ця звичка шкодить твоєму мозку». Під кожним вердиктом дрібний рядок: «Це експеримент на одній людині. Він говорить про тебе, а не про всіх».

**Бібліотека експериментів (6 шаблонів):** телефон поза спальнею; без скролу за годину до сну; без кави після 15:00; перші 30 хв після пробудження без телефона; 10 хв денного світла вранці; сповіщення вимкнені до обіду. Плюс власний експеримент (назва + опис A і B).

**Ціна скролу (SHOULD, Етап 4):** пара швидких тестів «до» і «після» сесії скролу, яку людина сама позначає кнопками. Результат пари не входить у Форму. Середнє показується лише після ≥ 5 пар, з підписом «сигнал, а не висновок: на результат впливає й втома, і час доби».

### Екран 1 — Лендинг (`/`)

Мета: за 10 секунд зрозуміти, що це, і почати демо. Великий заголовок «Твоя увага. Твої дані. Твої експерименти.» (EN: «Your attention. Your data. Your experiments.»), під ним одне речення про місію і кнопка «Спробувати 60 секунд» (запускає демо без збереження). Нижче три блоки-принципи (дзеркало, а не монітор; дані не залишають телефон; експерименти, а не заборони), короткий абзац «Чому я це зробила» від засновниці (текст напишу сама) і перемикач мови. Стиль Linear: багато повітря, одна акцентна деталь (анімоване кільце Форми, яке один раз заповнюється).

### Екран 2 — Онбординг (максимум 3 екрани)

(1) «Тобі є 18?» + згода з коротким текстом і посиланням на повну сторінку приватності. (2) Як працює тест: ілюстрація лічильника, три рядки тексту. (3) О котрій тобі зручно тестуватись щодня (вибір вікна) + «Встановити на головний екран» з інструкцією для iOS/Android. Стиль Opal: одна ідея, один заголовок, одна кнопка.

### Екран 3 — Тест (`/test`)

Завжди однаковий, незалежно від теми й часу доби (MUST: колір і яскравість стимулу впливають на час реакції). Майже чорний фон, по центру моноширинний лічильник у бурштиновому кольорі, що з'являється й біжить. Перед стартом: «Торкнись будь-де, щоб почати» і відлік 3–2–1 плавним колом. Знизу волосяна лінія прогресу з низьким контрастом. Жодних кнопок, іконок, навігації. Вихід — лише свайп униз або системна «назад», з підтвердженням «Перервати тест?».

### Екран 4 — Сьогодні (`/today`)

Герой: кільце Форми з числом (наприклад, 87) і підписом «у звичних межах». Навколо кільця тонка дуга звичного діапазону. Під кільцем «підпис дня» одним реченням і дрібні цифри: типова реакція, провали. Потім чек-ін чипами: сон (годин), якість сну, настрій, «була тривога вночі», теги. Якщо активний експеримент — картка «Сьогодні ввечері: умова B — телефон за дверима». До калібрування замість числа — «Калібрування 3/5» і коротке пояснення.

### Екран 5 — Історія (`/history`)

Графік Форми за 60 днів: точки сеансів, заштрихована смуга звичного діапазону, маркери умов A/B. Дотик до графіка відкриває повноекранний режим зі скрабінгом пальцем (як у Tide Guide): під пальцем — дата, Форма, сон, теги. Нижче — простий список сеансів.

### Екран 6 — Експерименти (`/experiments`)

Бібліотека з 6 карток і кнопкою «Свій експеримент». Активний експеримент: сітка 14 днів (кожна клітинка — A або B, заповнена після валідного сеансу), лічильник «ще N днів до першого висновку». Вердикт: горизонтальна шкала навколо нуля з точкою Δ та відрізком довірчого інтервалу, над нею — вердикт людськими словами, під нею — «Це експеримент на одній людині».

### Екран 7 — Приватність (`/privacy`)

Дві колонки у стилі етикеток Apple: «Що NeRN рахує з тебе» / «Чого NeRN не робить ніколи». Далі: де лежать дані, кнопки «Експортувати все» і «Видалити все», версія згоди, текст «Чому так» (про поведінкові проксі — напишу сама на основі мого есе).

### Екран 8 — Налаштування (`/settings`)

Мова, вікно тестування, тема (системна / світла / темна — не впливає на екран тесту), встановлення на головний екран, про проєкт, контакт для відгуків (mailto).

## Дизайн-система

Настрій: спокійна наукова лабораторія вночі — темні глибокі поверхні, один теплий акцент, точні цифри. Усі значення нижче — CSS-змінні в `src/ui/tokens.css`; компоненти не містять жорстко прописаних кольорів.

| Токен | Темна тема | Світла тема | Де використовується |
| --- | --- | --- | --- |
| `--bg` | #0B0C10 | #F6F4EF (тепле паперове) | Фон |
| `--surface` | #15171E | #FFFFFF | Картки, листи |
| `--text` | #F1EFE9 | #17181D | Основний текст |
| `--muted` | #8B8E99 | #6A6D77 | Підписи, одиниці |
| `--accent` | #FFB547 | #D98A12 | Кільце Форми, головні кнопки |
| `--band` | #5FC4AE | #2E9C86 | Звичний діапазон, «у звичних межах» |
| `--below` | #A395FF | #6C5CE7 | «Нижче звичного» (замість червоного) |
| `--stimulus-bg` | #050507 | #050507 | Екран тесту, завжди однаковий |
| `--stimulus` | #FFB547 | #FFB547 | Лічильник тесту, завжди однаковий |

**Типографіка.** Основний шрифт — **Fixel** від MacPaw (SIL OFL 1.1, повна кирилиця): Fixel Text для тексту (400 / 500 / 600), Fixel Display для великих чисел і заголовків (600). Запасний — Onest, далі `-apple-system, system-ui, sans-serif` (на iPhone і Mac це системний SF Pro; сам SF Pro **не вшиваємо** — ліцензія Apple цього не дозволяє). Inter, Poppins, Montserrat, Space Grotesk, Roboto — не використовуємо: це «дефолтні» шрифти згенерованих інтерфейсів. Цифри — `font-variant-numeric: tabular-nums`, щоб числа не «стрибали». Лічильник тесту — JetBrains Mono (OFL). Шрифти **самохостяться**: Fixel — woff2-файли з офіційного репозиторію MacPaw/Fixel разом із `OFL.txt` у `public/fonts/`; Onest і JetBrains Mono — через пакети @fontsource. Жодних запитів до Google Fonts: це теж про приватність. Шкала: 12 / 14 / 16 / 20 / 28 / 40 / 72 px; число Форми — 72 px, вага 600.

**Без «ШІ-естетики» (MUST).** Жодних фіолетово-синіх градієнтів, градієнтного тексту, світіння (glow), «скла» (glassmorphism), розмитих плям-блобів, емодзі замість іконок, іскорок ✨, шаблонних hero-блоків і однакових карток із тінню. Характер створюють типографіка, сітка, точні цифри й один теплий акцент.

**Сітка й форма.** Відступи кратні 4 px; радіус карток 20 px, кнопок 14 px; мобільний макет до 480 px ширини по центру на великих екранах; безпечні зони через `env(safe-area-inset-*)`.

**Рух.** Переходи 160–240 мс, ease-out; кільце Форми заповнюється один раз на день, 900 мс, м'яка пружина. `prefers-reduced-motion` вимикає все, крім миттєвих змін. На екрані тесту немає жодної анімації, крім самого лічильника.

**Фон протягом дня (SHOULD).** На екрані «Сьогодні» градієнт фону плавно зміщується: 5–11 год — тепліший відтінок, 11–18 — нейтральний, 18–5 — глибший синій. Це не стосується екрана тесту.

**Доступність (MUST).** Контраст тексту за WCAG AA; зони дотику ≥ 44 × 44 px; усі стани передаються і кольором, і словами; aria-мітки на кільці й графіках (наприклад, «Форма 87 зі 100, у звичних межах»); повна навігація з клавіатури у веб-версії. Чесна примітка на сторінці «Про проєкт»: тест візуальний і не підходить людям з порушеннями зору.

**Іконки.** Lucide, товщина лінії 1.5, лише там, де без іконки гірше зрозуміло. Іконка застосунку й логотип — окреме завдання для художниці, агент робить тимчасову нейтральну іконку (коло з точкою).

## Приватність і етика як архітектура

У MVP жоден байт даних людини не залишає її пристрій — це перевіряється технічно, а не обіцяється текстом.

**Технічні вимоги (MUST):**

1. Жодних сторонніх запитів: без аналітики, без трекерів, без CDN, без Google Fonts. У DevTools на вкладці Network після першого завантаження мають бути лише запити до власного домену.
2. Строгий Content-Security-Policy у `netlify.toml`: `default-src 'self'`, `connect-src 'self'`, без `unsafe-eval`.
3. Service worker кешує лише статичні файли застосунку, ніколи не дані.
4. Нуль cookies. Нуль ідентифікаторів пристрою, що покидають пристрій.
5. `fingerprint` у DeviceInfo — локальний хеш лише для розмежування сегментів базової лінії, ніколи не передається.
6. Кнопки «Експортувати все» (JSON + CSV) і «Видалити все» (з підтвердженням введенням слова «видалити»).
7. Вік: без підтвердження 18+ застосунок працює лише в демо-режимі й нічого не зберігає.

| Що NeRN рахує з тебе | Чого NeRN не робить ніколи |
| --- | --- |
| Швидкість реакції, провали, фальстарти | Не робить медичних висновків і діагнозів |
| Форму дня відносно тебе самої | Не порівнює тебе з іншими людьми |
| Результати твоїх експериментів | Не вгадує емоції, настрій чи особистість |
| Те, що ти сама вписала в чек-ін | Не читає інші застосунки, геолокацію, контакти, мікрофон |
| — | Не продає, не передає і не бачить твоїх даних |

**Етична логіка (для тексту «Чому так»).** Час реакції — це поведінковий проксі стану мозку, і саме такі дані найслабше захищені законами. Тому NeRN робить захист частиною конструкції: дані, яких немає на сервері, неможливо злити, продати чи вимагати. Текст сторінки пише засновниця; агент ставить заглушку з позначкою `TODO(Dinara)`.

**Юридичний мінімум.** Навіть без збору даних потрібні: коротка політика приватності, умови використання з фразою «не медичний пристрій», дата версії згоди. Агент готує чернетки-шаблони, засновниця перевіряє. Для Фази 2 політику оновити до початку збору будь-яких даних.

## Фаза 2: Пульс країни і шар повітряних тривог

Фаза 2 починається лише після того, як MVP має ≥ 30 активних користувачів, і лише з моєю окремою командою агенту. Мета: анонімно показати, що відбувається з увагою людей після ночей із тривогами, не дізнаючись нічого про конкретну людину.

**Шар тривог — регіон не залишає телефон.** Щоночі cron-воркер на Cloudflare Workers забирає історію тривог і публікує статичний файл `alerts/YYYY-MM-DD.json` з позначкою для **кожної** області: чи була тривога між 23:00 і 07:00 і скільки хвилин. Застосунок завантажує весь файл і сам вибирає свою область локально, тож сервер не знає, де людина. Автоматичне значення лише пропонується в чек-іні, людина може його змінити.

Джерела даних: [alerts.in.ua](https://alerts.in.ua/) дає API за токеном, який видають через форму запиту; за описом розробників, форма відхиляє однорядкові й згенеровані ШІ запити, тож заявку **пишу сама, своїми словами**, з описом використання й частоти запитів. Його історія охоплює приблизно 30 днів, тому воркер має накопичувати дані сам із першого дня. Для довшої історії є волонтерське джерело raid.fly.dev ([огляд джерел](https://glama.ai/mcp/servers/mvxbg2h7vi)). Усі ці сервіси тримають волонтери: запити — рідко (раз на ніч), з кешем і подякою на сторінці «Про проєкт».

**Пульс — анонімний внесок за згодою.** Окремий екран згоди, за замовчуванням вимкнено. Раз на день, після валідного сеансу, надсилається лише:

```ts
interface PulseSubmission {
  date: string;           // 'YYYY-MM-DD', без часу
  region: string;         // область, яку людина вибрала сама
  formaBucket: number;    // Форма, округлена до 5 (напр. 85)
  nightAlert: boolean;    // з чек-іну
  ageBand: '18-24' | '25-34' | '35+';
  dayToken: string;       // випадковий, новий щодня — лише щоб рахувати 1 внесок на день
}
```

Жодних ідентифікаторів, сирих реакцій, тегів, експериментів чи нотаток. Сервер (Worker + D1) не логує IP-адреси, зберігає лише агрегати по днях. Правило k-анонімності: область-день показується лише при ≥ 20 внесках, інакше вливається в загальнонаціональне число.

**Публічна сторінка «Пульс».** Середня Форма по Україні за 30 днів і порівняння «ночі з тривогою / без» — лише коли даних достатньо. Під кожним числом обов'язковий підпис: «Це вибірка людей, які самі користуються NeRN. Це кореляція, а не доказ причини».

**Контекст і скромність:** такий самий інтерес до тривог як прихованого фактора сну вже є в інших — наприклад, відкритий проєкт kyiv-alerts записує історію тривог саме для аналізу сну. Тому NeRN подає пульс не як «перший у світі», а як інструмент, що дає людям бачити це на собі.

## Тексти, тон, i18n

NeRN говорить як уважна подруга, що знається на науці: тепло, коротко, чесно, без вигуків і без повчань. Мова інтерфейсу за замовчуванням — мова браузера (uk або en), перемикач у налаштуваннях і на лендингу.

**Правила тексту (MUST):**

- Звертання на «ти» в українській, «you» в англійській.
- Речення до 12 слів в інтерфейсі; пояснення — до 3 речень.
- Жодних знаків оклику, крім «Новий пік!».
- Замість «погано / провал / помилка» — «нижче звичного», «пропуск», «зарано».
- Усі тексти лежать у `src/i18n/uk.ts` і `en.ts`, ключі типізовані; збірка падає, якщо ключ відсутній в одній з мов.
- Українські множини через `Intl.PluralRules('uk')` (1 день, 2 дні, 5 днів).
- Дати й числа через `Intl.DateTimeFormat` / `Intl.NumberFormat` відповідно до мови.

| --- | --- | --- |

**Підпис дня.** 20–30 шаблонів на мову, обираються за станом (пік, у межах, нижче, калібрування, після ночі з тривогою) і не повторюються два дні поспіль. Приклад: «Увага на звичному рівні. Хороший день, щоб зробити складне першим». Без ШІ-генерації.

## Тестування, якість, продуктивність

Цифри в NeRN мають бути правильними, тому статистика й таймінг покриваються тестами раніше за інтерфейс.

**Юніт-тести (Vitest), MUST:**

- `stats/`: S, медіана, провали, фальстарти на відомих наборах RT з ручно порахованими відповідями.
- Форма: калібрування, стеля як 90-й перцентиль, обмеження 100, «новий пік», зміна сегмента пристрою.
- Експерименти: генерація пар A/B з seed; виключення сеансів (калібрувальні, поза вікном, невиконана умова); bootstrap-інтервал відтворюваний з тим самим seed; усі 4 вердикти.
- Рушій PVT з імітованим годинником: паузи в межах 1–4 с, фальстарт перезапускає паузу, тайм-аут 10 с дає miss, прихована вкладка робить сеанс невалідним.
- i18n: кожен ключ є в обох мовах.

**E2E (Playwright), MUST:** перший запуск → 18+ → тест (прискорений годинник) → результат; щоденний сеанс → чек-ін → історія; старт експерименту; експорт і видалення даних; перемикання мови.

**Ручна перевірка таймінгу (MUST перед запуском).** Відеозйомка екрана телефона 240 fps під час 20 стимулів: різниця між часом на відео й записаним RT має бути сталою в межах ±1 кадру дисплея. Перевірити на iPhone (Safari) і Android (Chrome). Результат записати в `docs/timing-check.md`.

**Продуктивність і якість (MUST):** Lighthouse на мобільному ≥ 95 для Performance, Accessibility, Best Practices; перший JS-бандл ≤ 150 КБ gzip; повна робота офлайн після першого відкриття; жодних помилок у консолі; TypeScript strict без `any`; ESLint + Prettier у CI (GitHub Actions) на кожен push.

## Протокол роботи для Claude Code

Ці правила важливіші за швидкість: мета — продукт, який я розумію і можу захистити на співбесіді, а не максимум коду.

2. **Один етап — одна гілка** (`stage-1-test` тощо), маленькі коміти з повідомленнями англійською в стилі Conventional Commits.
3. **Тести перед логікою** для `src/engine/` і `src/stats/`: спершу тест з очікуваним числом, потім реалізація.
4. **Нові залежності — лише з дозволу.** Перед `npm install` поясни, навіщо пакет і чи можна без нього.
5. **Жодних мережевих запитів** у коді MVP. Якщо здається, що без них ніяк, — зупинись і спитай.
6. **NOT NOW — табу.** Не додавай ШІ, акаунти, аналітику, сенсори, соцфункції, навіть якщо «це займе 5 хвилин».
7. **Не вигадуй науку.** Будь-яке число чи поріг, яких немає в цьому ТЗ, — спершу питання мені.
